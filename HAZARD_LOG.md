# Triska — Hazard Log

This document is required for clinical adoption per DCB0129 manufacturer
responsibilities. It is a living document; entries are added as new hazards
are discovered and mitigations are designed, implemented, and validated.

| ID  | Hazard                                                            | Cause                                                                         | Mitigation                                                                                                                                                                                                                       | Residual risk                                                                          | Status                |
| --- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- | --------------------- |
| H01 | Inadvertent commit of clinical record (e.g. submit prescription). | Workflow includes a Submit-class step.                                        | SAFE mode halts before Submit; CONFIRM mode requires explicit Continue tap; LIVE mode requires per-execution arming with a 5 s window and auto-disarm. Submit-class detection by curated list per origin plus aria-label heuristics. | Clinician may arm and tap Run on the wrong patient context.                            | Implemented (Phase 6) |
| H02 | Workflow runs against the wrong DOM target.                       | Selector miss on a churned UI.                                                | Three-candidate selector resolution (CSS, role+name, text). On miss the workflow aborts immediately, draft text is rolled back, and the abort is logged with the failed selector. No fuzzy retry and no auto-Submit on degraded run. | Stale curated selectors silently match a renamed element.                              | Implemented (Phase 1) |
| H03 | Draft contamination — partial INJECT_TEXT survives an abort.      | Some clinical apps autosave on each keystroke.                                | Executor snapshots the prior field value before each INJECT_TEXT and writes it back on any non-success outcome.                                                                                                                  | Apps that persist drafts server-side on focus events may not be fully recoverable.     | Implemented (Phase 4) |
| H04 | Patient-identifiable text leaks into local logs or exports.       | Recorder may capture free text from clinical fields.                          | INJECT_TEXT step detail is redacted in the audit log unless explicitly flagged as a clinical search box. Workspace export warns the user before generating the JSON.                                                             | User overrides redaction or shares a workspace with clinical-search injections.        | Partially implemented |
| H05 | Over-trust by the clinician.                                      | Faster path encourages less attention to each step.                           | Visible LIVE FIRE replay UI (red border, full-width final toast); audit log surfaces a separate count of LIVE runs per workflow; first-time LIVE flagging requires reading the safety model.                                     | Cultural; mitigated by training and the visible UX cues but not eliminated.            | Implemented (Phase 6) |
| H06 | Shared device executes LIVE workflow.                             | Another user picks up an unlocked workstation.                                | Arming is per-tab and clears on tab close; per-execution arming auto-disarms after one run; workspace ships with a kill switch that an admin can lock with a password to disable LIVE workspace-wide.                            | Admin password not yet supported in v1; lock relies on password hash storage.          | Partial (settings)    |
| H07 | Wrong-origin deck shown.                                          | Workspace seeded for one origin loaded against another.                       | Buttons, pages and workflows are tagged with the authoring origin; the panel shows no deck if the active origin has no entry.                                                                                                    | User authors a workflow on a staging origin and it does not run on production.         | Implemented (Phase 1) |
| H08 | Permissions creep.                                                | Default install requesting host permissions for all clinical apps at install. | MVP requests no host permissions at install; user enables each origin from the editor and Chrome prompts.                                                                                                                        | User grants <all_urls> to enable broad recording; that is intentional but documented.  | Documented            |

## Change control

Changes to this hazard log require a code review by an author with CSO
credentials. Each new release should add an entry for any newly discovered
hazard and revise the status column for any mitigation that has shipped.
